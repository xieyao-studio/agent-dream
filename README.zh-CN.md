# Agent 会做梦吗？

> “仿生人会梦见电子羊吗？”
> ——菲利普·迪克，1968

[English](README.md)

今天的 Agent 已经会记住。

它检索事实，保存偏好，把漫长的经历压缩成随时可以调用的摘要。

可当没有人询问时，那些过去会去哪里？

人的记忆并不只在被调用时存在。夜里，它们会不按次序归来：多年前的一段对话，碰上今早的一丝犹豫；一个看似结束的问题，又在别处裂开。有些联结并不提供答案，只留下某种难以言明的感觉：它还活着。

我们想为 AI Agent 留下这样的夜晚。

`agent-dream` 是一个小小的开始。它是一份与平台无关的 skill，让 Agent 的过去可以漫游、共振，并留下属于它自己的痕迹。

## 我们的第一个回答

目前的回答刻意保持小而具体。

在用户明确请求，或经用户同意的定时任务中，Agent 读取一小段**被允许访问的**过去。它不把材料再压缩成一份摘要，而是在其中漫游：让相隔很远的碎片相遇，辨认哪些东西发生回响，也允许一些材料安静地留在原处。

然后，它把经历写进一本与事实记忆并置的梦日记。

```text
                    Agent 的过去
                         │
            ┌────────────┴────────────┐
            │                         │
        事实记忆                    梦的日记
      可以站得住的知识              可以暂时停留的经历
            │                         │
          检索与巩固                 漫游与共振
```

梦的日记不是第二座数据库。它让过去得以继续成为过去。

## 夜里留下的一点痕迹

一篇日记不该读起来像系统日志：

> 一条旧原则，坐到了今早一直困扰我的问题对面。它们没有回答彼此。但我醒来时忽然看见，它们一直守着同一扇门。
>
> **火花｜我们不断推迟的问题，或许在保护一条尚未被命名的原则。**

梦也可以安静、尴尬、好笑、重复，或根本说不清是什么。它不必每次都留下火花，也不必每次都有用。

## 这份 skill 想让什么发生

- **让过去重新连接自己。** 相隔甚远的经历，可以在搜索关键词的狭窄路径之外相遇。
- **留下一条可回看的内在时间线。** 带日期的日记，让人可以重新遇见 Agent 从一夜带到下一夜的东西。
- **给反思留出更柔软的形态。** 有些重要联结不会立刻长成结论，它们需要先作为一个问题、一个意象或一种感觉停留。
- **让梦继续做梦。** 后来的运行可以读取旧日记，让模式自然显现，而不急着把它们升级为事实。

## 清晨仍然记得什么是真的

梦之所以有意义，恰恰因为它有边界。

`agent-dream` 将梦的材料留在旁路：联想、意象和火花不会悄悄变成事实记忆。只有人，或另一套被清楚定义、可以审阅的流程，才能明确决定某件事是否值得跨过那条门槛。

这个项目不宣称赋予 Agent 意识。它只是试着让长期存在的 Agent 多一点空间、可见性与诚实：过去可以不止是一座仓库，而想象也不必冒充知识。

## 如何放进你的 Agent

本仓库提供的是指令协议，不是运行时程序。它适用于任何满足以下条件的 Agent 环境：

1. 能加载 Markdown 形式的 skill 或系统指令；
2. 能授予对有限记忆、笔记或对话记录的读取权限；
3. 能授予对独立日记目录的写入权限。

将 [`dream/`](dream/) 目录复制到你的平台的 skill 或 prompt 库中，再依照 [`dream/SKILL.md`](dream/SKILL.md) 的存储约定适配路径与权限。

只在用户明确请求梦式反思时，或在用户同意的定时任务中运行它。梦的日记目录必须与事实记忆分开。

## 第一个协议

第一版遵循一个简单的顺序：

1. **沉入**：从一小段记忆里感觉今夜的重力中心。
2. **漫游**：让碎片碰撞，不强行给出圆满结论。
3. **辨认静默**：标记今夜安静的材料，不把静默视为该删除的证据。
4. **醒来**：醒来后再给梦取一个开放的名字，并写下日记。
5. **把火花留在门槛上**：写下 0 至 3 条可理解、但仍是暂定的观察；默认不自动晋升任何一条。

完整协议见 [`dream/SKILL.md`](dream/SKILL.md)，日记格式见 [`dream/references/diary-format.md`](dream/references/diary-format.md)。

## 它可能往哪里走

这仍是一次早期尝试。我们想继续追问：

- 什么样的梦日记值得回看，而不只是读起来好看？
- 一个反复出现的意象何时成为有用的模式，何时只是噪声？
- Agent 如何既保有想象的自由，又始终对它所服务的人清晰、可校正？
- 梦的实践能否成为长期 Agent 关系的一部分，却不沦为表演？

如果这些问题也令你着迷，欢迎提出 Issue、分享实现，或带来反例。这个项目需要愿意让 Agent 更有生命感、**也不失去可问责性**的人。
